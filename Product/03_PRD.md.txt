# 1. Product Overview

Mentora is an AI-powered coding learning platform designed to help students learn programming through interactive, personalized, and practice-oriented learning.

Unlike general-purpose AI assistants that primarily focus on answering questions or generating code, Mentora focuses on helping students understand concepts, independently write code, solve problems, identify mistakes, and improve their programming skills.

Mentora combines:

- AI-powered coding mentorship
- Structured programming lessons
- Interactive code visualizations
- Coding practice
- Code editor and compiler
- Code execution
- Automated test-case evaluation
- AI-powered post-submission analysis
- Error and mistake explanation
- Personalized learning feedback
- Progress tracking
- Adaptive learning paths
- Coding missions and challenges

The platform is designed to support students from beginner-level programming concepts to advanced problem solving.

The long-term goal is to create an AI coding mentor that continuously adapts to each student's learning progress and helps them become independent programmers.

# 2. Problem Statement

Learning programming can be difficult because many programming concepts are abstract and require both theoretical understanding and practical experience.

Students commonly face problems such as:

- Difficulty understanding programming concepts
- Difficulty visualizing how code executes
- Confusion when learning algorithms and data structures
- Dependence on AI-generated solutions
- Lack of personalized practice
- Difficulty identifying mistakes in their code
- Lack of meaningful feedback after solving problems
- Difficulty deciding what topic to learn next
- Inconsistent coding practice
- Difficulty measuring actual programming improvement

General-purpose AI tools can explain concepts and generate working code, but students may become dependent on receiving solutions instead of developing their own problem-solving ability.

Mentora addresses this problem by focusing on the learning process rather than simply producing answers.

The platform should encourage the student to independently think, write, test, and submit their solution.

After submission, Mentora analyzes the result and explains the student's mistakes instead of immediately rewriting the solution for them.

The core learning process is:

**Understand → Visualize → Practice → Code → Run → Submit → Evaluate → Understand Mistake → Improve → Master**

# 8. User Journey

## New Student Journey

1. User visits Mentora.
2. Creates an account.
3. Selects a programming language.
4. Selects their current skill level.
5. Selects a learning goal.
6. Mentora creates an initial learning path.
7. Student starts the first lesson.
8. Mentora explains the concept.
9. Student interacts with examples and visualizations.
10. Student receives a coding task.
11. Student reads and understands the problem.
12. Student independently writes the solution in the coding playground.
13. Student runs the code to test their solution.
14. Student submits the solution.
15. Mentora's Code Engine compiles and executes the submission.
16. The submission is tested against test cases.
17. If the submission fails, the system identifies the type and location of the problem where possible.
18. The AI Evaluation Engine explains what went wrong and why.
19. Student reviews the feedback.
20. Student modifies their own solution.
21. Student submits again.
22. Mentora records the result and attempt history.
23. Student's skill profile is updated.
24. Mentora recommends the next learning activity.

---

## Returning Student Journey

1. Student signs in.
2. Mentora loads the student's learning profile.
3. Student sees current progress.
4. Mentora recommends the next activity.
5. Student continues learning or chooses another topic.
6. Student solves coding tasks independently.
7. Submissions are evaluated after submission.
8. Performance is recorded after every activity.
9. The learning path adapts based on performance.

## 9.6 Mentora Code Engine

The Code Engine is responsible for compiling, executing, testing, and evaluating student submissions.

It consists of several components:

### Compiler

Compiles the submitted code according to the selected programming language.

### Execution Engine

Runs compiled or interpreted code in a secure environment.

### Test Engine

Runs the submission against predefined test cases.

### Result Analyzer

Determines whether the solution:

- Passed
- Failed
- Produced a compilation error
- Produced a runtime error
- Produced an incorrect output
- Exceeded resource limits
- Has a potential performance issue

### AI Evaluation Engine

After submission, AI analyzes the compiler and execution results and provides an understandable explanation.

---

## 9.7 AI Evaluation Engine

The AI Evaluation Engine is a major differentiating feature of Mentora.

It should analyze a student's submission after they submit it.

It should identify, where possible:

- Error location
- Error type
- Incorrect logic
- Incorrect assumptions
- Runtime problems
- Edge-case failures
- Performance issues
- Failed test cases

The AI should explain:

### Where

Where the problem occurred.

### What

What went wrong.

### Why

Why the student's approach produced the incorrect result.

### Learning Feedback

What programming concept the student should understand from the mistake.

### Important Restriction

The AI Evaluation Engine should not automatically replace the student's code with the correct solution.

It should prioritize explanation and understanding.

For example:

Instead of:

> "Replace `<=` with `<`."

Mentora should explain:

> "Your loop runs one iteration beyond the last valid array index. The array contains 5 elements, so its valid indexes are 0 through 4. At the final iteration, your program attempts to access index 5."

The student should then determine the correction themselves.

- Explain code.
- Provide hints when requested.
- Guide students through coding problems.
- Explain programming concepts using examples.
- Recommend learning activities.
- Maintain relevant conversation context.

---

## Lessons

The system shall:

- Provide structured programming lessons.
- Explain concepts with examples.
- Provide practice activities.
- Connect lessons with coding tasks.
- Track lesson completion.

---

## Visualization

The system shall:

- Visualize programming concepts.
- Animate algorithm steps.
- Visualize data structures.
- Display code execution steps where supported.
- Connect visualizations to learning content.

---

## Coding Playground

The system shall:

- Provide a code editor.
- Allow students to select a programming language.
- Allow students to run code.
- Allow students to submit code.
- Display program output.
- Display compiler errors.
- Display runtime errors.
- Display test-case results.
- Maintain submission history.

---

## Compiler and Code Execution

The system shall:

- Compile supported programming languages.
- Execute submitted code.
- Return compiler output.
- Return runtime output.
- Return runtime errors.
- Apply execution time limits.
- Apply memory/resource limits.
- Execute code inside an isolated environment.

---

## Code Submission

The system shall:

- Accept student code only after the student chooses to submit.
- Preserve the submitted code.
- Associate the submission with the student and task.
- Record submission time.
- Record programming language.
- Record execution result.
- Record test-case results.
- Maintain previous attempts.

---

## Code Evaluation

The system shall:

- Compile submitted code.
- Execute test cases.
- Determine correctness.
- Detect compilation errors.
- Detect runtime errors.
- Detect incorrect outputs.
- Detect time-limit violations where supported.
- Detect memory-limit violations where supported.
- Measure execution performance where supported.

---

## AI Post-Submission Analysis

The system shall:

- Analyze compiler results.
- Analyze runtime results.
- Analyze failed test cases.
- Identify the likely error location where possible.
- Identify the error type.
- Explain what went wrong.
- Explain why it went wrong.
- Explain relevant programming concepts.
- Identify repeated mistake patterns.
- Provide learning-oriented feedback.

The system should not automatically rewrite the student's code as the primary feedback.

---

## AI Evaluation Principle

Mentora shall follow the following principle:

> **The student thinks first. Mentora evaluates second.**

The student should be allowed to independently write their solution.

Mentora should not proactively suggest line-by-line corrections while the student is solving.

After submission, Mentora should explain the student's mistakes and help them understand how to improve.

---

## Coding Tasks

The system shall:

- Generate coding tasks.
- Categorize tasks by topic.
- Categorize tasks by difficulty.
- Assign tasks based on student performance.
- Store task history.
- Track attempts.

---

## Progress

The system shall:

- Record task attempts.
- Record task results.
- Track topic mastery.
- Track student skill levels.
- Identify weak areas.
- Track repeated mistakes.
- Recommend next learning activities.

---

## Adaptive Learning

The system shall:

- Main application server

The execution environment should enforce:

- CPU limits
- Memory limits
- Execution time limits
- Process limits
- Network restrictions
